**Status:** plan, written 2026-08-17 against the code as it stands, not against the specs.
**Rule for this document:** every "missing" is something I checked. Where a spec and the
code disagreed, the code won.

---

## The shape of the plan

Two halves, in this order, and the order is the decision:

> **Finish everything we can on our side. Then build the app.**

The app is the surface a provider points at — graph, score, runnable workflow, rehearsal,
drift. It is the deliverable. It is also the thing that will expose every soft claim
underneath it, which is why it comes second. **A page that publishes a score we cannot
defend is a one-way door**, and the score is not yet defensible at catalogue scale.

## Phase 1 — make the score defensible

**Why first:** this is the only phase whose absence makes later phases actively harmful.
Everything else is slower-than-ideal; this one is wrong-in-public.

Our strongest claim is a second opinion on an address: a wrong-but-well-formed derivation
compiles clean, simulates clean, points at the wrong account, and only an independent
derivation catches it. That independence is real today **for one program**, where
`scripts/roundtrip_let_me_buy.py` checks against a hand-written `receipts_pda`.

At catalogue scale it evaporates. `gecko/project/probes.py` derives addresses from the
graph's own seed recipe and the judge reads the same graph — probe, derivation and verdict
all descending from one comprehension. **That is the same structure as the defect we caught
in someone else's stack, and the same structure as both of this week's withdrawals.**
Simulation is not a fallback: a wrong-but-well-formed address is precisely what it cannot
catch.

**1a — cross-source disagreement as the witness.** Derive once from the IDL alone, once from
source recovery, and score the *disagreement*. Both extractors already exist
(`from_anchor_idl` and `from_source` in `gecko/pda_extract.py`); nothing currently compares
them as independent opinions rather than merging them. This is genuine independence, and it
is the cheapest real fix available.

**1b — chain corroboration.** A derived address that holds no account, or holds one the
program does not own, or whose discriminator is not the expected type, is a signal the chain
gives away free. Three cheap reads, and they catch the case 1a cannot: both extractors
agreeing and both being wrong.

**1c — decide the public claim.** Today's honest sentence is *"derived, and the chain shows
an account of the expected type at it"* — not *"the address is right"*. That wording is a
one-way door once a score is published. **Founder call, and it gates the first catalogue
run.**

## Phase 2 — make it a stage, not a script

Mechanical, and can run alongside Phase 1.

**2a — `gecko/score.py`.** The five questions as a library function over a graph, returning
a typed result. `scripts/catalog_ci.py` becomes a thin caller. Until this exists the score
cannot be run by anything but a human at a terminal.

**2b — `gecko/ingest` as a front door.** One entry point that takes an IDL, an OpenAPI
document, or a docs URL and returns a graph. The pieces exist and are reached individually.

**2c — probes as declarative shapes, not Python.** Open: adopt SHACL, or a smaller shape
language of our own. SHACL is the standard and makes a score something a provider can read
and dispute; it also drags in RDF vocabulary nothing else here speaks. **Not decided.**

## Phase 3 — unattended, on one program

The step the CI-for-agents spec has been calling for since it was written, and the first
thing that is a *product* rather than a measurement.

**3a** — one catalogue entry, generated probes, all five questions per instruction, on a
schedule, score published. Six instructions holding without a human is the proof the same
loop runs for four thousand.

**3b** — drift: re-run on change and say *which* of the five answers moved. `gecko/drift.py`
exists; nothing runs it. This is the recurring value for a provider — "something changed" is
noise, "your flow now reports a cost it will not charge" is a reason to renew.

## Phase 4 — catalogue scale

**4a — the 123 unresolvable PDAs.** 6% of accounts still need a human, and 59% of them sit
in three programs. Seed recovery from source is the tool; this is applying it in bulk.

**4b — declared-vs-raised.** An error code in an IDL reads to an agent as a guarantee.
`StoreNotEmpty` is declared in one program's IDL and raised nowhere in its source — we
proved it by deleting a live storefront in simulation at 16,893 CU. Generalising this needs
source ingestion at scale, so it follows 4a. **It is also the sharpest finding we can
publish**, because no IDL-derived surface can see it.

**4c — REACHABLE.** `search_hybrid_scored` takes a `dense_index` *parameter* and nothing on
the MCP surface constructs one: the hybrid path is **built and not wired**. Lexical scores
0.00 on paraphrase intents across four APIs. Wiring it is small; the evidence gate for
flipping it on (ops > 50 and lexical recall@3 < 0.8) already exists and should be honoured
rather than bypassed.

## Phase 5 — the app

Only after the above. What a provider points at:

the graph, browsable · the score per instruction, each answer measured and carrying its
origin · runnable workflow output they can copy · a rehearsal · drift, re-run on change.

Two constraints inherited from decisions already made. **The provider owns the page** — we
generate and host it, their name is on it, and we never rank one owner against another; that
is the line between this and a marketplace. And **`try_*` is loopback-only today**, so
"rehearse it in one click" has no delivery mechanism unless the developer runs their own
fork. Either that bullet is developer-local, or it comes off the page. **Founder call.**

## Running alongside — the contribution track

Independent of everything above, each item with a reproduction: the search operator that
makes 5 of 5 natural-language queries return nothing, the publish path that runs fewer
checks than the authoring loop, output wiring never validated. One PR, not eight. And the
`rpcUrl` SSRF posture, which we owe them even though closing it costs us a channel.

## What we cannot finish on our side

Named so they are not mistaken for oversights.

- **The fork endpoint.** We decided not to host one — it is a thin wrapper on something the
  Foundation is shipping. That leaves the Phase 5 rehearsal bullet open.
- **Willingness to pay.** Untouched by any of this, and no longer the topic — distribution
  first, and the roadmap above is the version of "something useful" we can actually build.

## The next implementation plan

**Phase 1a, and nothing else, until it holds.**

1. `gecko/witness.py` — take a program's IDL and its source, derive each account's address
   from each independently, and return a typed `Disagreement` per account: agree, disagree
   (with both addresses), or only-one-source-had-an-opinion.
2. Wire it into the score as its own axis. An account whose two derivations disagree is not
   a pass with a note — it is a finding, and it is the finding nothing else can produce.
3. Add chain corroboration (1b) as a second, weaker signal: exists · owned-by · type.
4. Re-run the 60-program scan and report **how often the two sources disagree**. That number
   has never been measured, and it is the number that says whether the witness is worth
   what it costs.
5. Only then answer 1c, with evidence rather than preference.
